# Own frame: our own d3d8.dll (branch frame-d3d8, 2026-10-30)

HiFi XI's own Direct3D 8 translator, in dgVoodoo 2.87's place: the game's Direct3D 8 calls become Direct3D 12 on the
game's own thread, with nothing closed between the game and HiFi XI. Built and tested offline only. **Nothing here has
been installed or run in game.**

## What's built
`build_d3d8.cmd` (called by `build.cmd`, which passes `quick` on: then the DLL alone) builds `build\d3d8\d3d8.dll`
(32-bit, exports `Direct3DCreate8`, `ValidatePixelShader`, `ValidateVertexShader`, `DebugSetMute`) and its tests.

| File | What |
|---|---|
| `src/d3d8/d3d8.cpp` | `Direct3DCreate8`, `IDirect3D8` (adapters and modes from DXGI, caps and format answers as dgVoodoo gives them), the log |
| `src/d3d8/device.cpp` | `IDirect3DDevice8`: state, resources, shaders and declarations, state blocks, CopyRects, UpdateTexture, GetFrontBuffer, Reset |
| `src/d3d8/device_draw.cpp` | the draw path: shaders and pipeline for the state, constants, textures and samplers, buffers, resource states, binding; Clear; Present |
| `src/d3d8/resource.cpp` | textures (2D, cube, volume), surfaces, vertex and index buffers, locks, uploads, readbacks |
| `src/d3d8/gpu.cpp` | the Direct3D 12 side: device, queue, the one command list, frame memory, descriptor heaps, barriers, the root signature |
| `src/d3d8/ffp.cpp` | the fixed function as generated HLSL |
| `src/d3d8/sm1.cpp` | vs.1.1 and ps.1.0-1.4 bytecode to HLSL |
| `src/d3d8/compile.cpp` | D3DCompile (Windows' d3dcompiler_47.dll), cached in memory and in `d3d8-shader-cache` beside the DLL |
| `src/d3d8/format.cpp` | the formats: GPU layouts, conversions, DXT decoding |
| `src/d3d8/present.cpp` | the swap chain and the gamma pass |

## How it records (and why HiFi XI runs on it unchanged)
- **Before its device** it asks the `dxgi.dll` beside the game for a factory (`CreateDXGIFactory2`, else 1), as dgVoodoo
  does: HiFi XI's starter starts HiFi XI there, its hooks in from the first list and view.
- **One direct list** on the game's thread. It's closed and submitted at Present, at a readback (a Lock of a surface a
  target was copied into: the game's visibility tests), and every 1024 draws. After each submit it's reset at once;
  descriptor heaps (one CBV/SRV/UAV, one sampler, both shader visible) and the root signature are set first, then the
  device binds again only what its next draw needs. Three frames in flight, each with its allocator, upload pages and
  share of the descriptor heap.
- **Lazy state, dgVoodoo's shape:** nothing reaches the list until a draw or clear needs it; then only what changed.
  The device remembers what it bound per list; HiFi XI's restore (`grass::list_state`) puts back exactly that.
- **What HiFi XI's hooks see, as with dgVoodoo** (all checked by `d3d8_hooks`):
  - render targets R8G8B8A8 (views 28 on typeless resources 27), depth D24S8 (views 45 on 44), all made through the
    hooked device;
  - viewports half a pixel in, depth 0..1 (MinZ/MaxZ in the shaders), scissors the viewport;
  - Clear in place: ClearRenderTargetView then ClearDepthStencilView, with the game's rects clipped to the viewport (none
    when that's the whole target); a 1x1 stencil-only Clear arrives as exactly that, the targets bound just before, its
    stencil plane put in DEPTH_WRITE just before;
  - the depth's planes follow what each draw writes (plane 0 DEPTH_WRITE with Z writes, DEPTH_READ without; plane 1 the
    same for stencil): barriers name subresource 0 or 1;
  - a target goes to PIXEL_SHADER_RESOURCE when sampled (the world's end: the resolve is the next draw, 4 vertices),
    RENDER_TARGET when drawn into; the back buffer to COPY_SOURCE at Present (copied into a flip swap chain's buffer).
- Root signature: root CBV b0 (vertex constants), root CBV b1 (pixel constants), a table of 8 SRVs, a table of 8
  samplers. Vertices through the input assembler (HiFi XI doesn't touch it). OMSetStencilRef only when stencil is on.

## What's supported
- `IDirect3D8` whole; `IDirect3DDevice8` whole except ProcessVertices and patches (logged, nothing drawn).
- Textures in A8R8G8B8, X8R8G8B8, R5G6B5, A1R5G5B5, X1R5G5B5, A4R4G4B4, X4R4G4B4, A8 (white with its alpha, as
  dgVoodoo), L8, A8L8, P8 (through the current palette at upload), A8R3G3B2, R3G3B2, V8U8, Q8W8V8U8, V16U16,
  X8L8V8U8, L6V5U5, A2B10G10R10, G16R16, DXT1-5; the formats dgVoodoo turns down (R8G8B8, A4L4, A8P8, UYVY, YUY2,
  DXT not in whole 4x4 blocks) are turned down too. Cube and volume textures, mip levels, LOD, managed / default /
  system memory pools, DYNAMIC, partial locks.
- Surfaces: render targets (lockable: read back), depth buffers (D16, D24S8, D24X8, D24X4S4, D15S1, D32), image
  surfaces, the back buffer; CopyRects in every direction (from a target into memory read at the next access), UpdateTexture,
  GetFrontBuffer (the back buffer's last picture). Multisampled targets resolved when read.
- Vertex and index buffers, 16- and 32-bit indices, DISCARD / NOOVERWRITE (dynamic ones stream from upload memory,
  others are copied up when locked and stream once locked again after drawing); multiple streams; base vertex;
  DrawPrimitive, DrawIndexedPrimitive and both UP draws; every primitive type (fans as lists).
- State blocks: recorded (Begin/End), made (ALL, PIXELSTATE, VERTEXSTATE), captured, applied, deleted.
- **Fixed function** (one shader pair per combination of what shapes the code; values in constants): transforms,
  vertex blending (up to 4 matrices), 8 lights (directional, point, spot), the material and its colour sources, ambient,
  specular, local viewer, normalization; vertex fog (linear, exp, exp2, range) and table fog (by w or z), fog for
  pretransformed vertices from the specular's alpha; texture coordinate indices, generation (camera-space normal,
  position, reflection) and matrices (COUNT1-4, PROJECTED); 8 stages with every operation, argument modifiers,
  RESULTARG TEMP, bump mapping (BUMPENVMAP, BUMPENVMAPLUMINANCE); alpha test (on the 8-bit alpha), blending including
  REVSUBTRACT/MIN/MAX, colour write masks, stencil, ZBIAS (dgVoodoo's measured bias), cull, fill, flat shading, user
  clip planes. Pretransformed vertices through the viewport with perspective kept.
- **vs.1.1** (every instruction, relative addressing, the declaration's constants, def) and **ps.1.0-1.4** (arithmetic
  with every modifier, co-issue, tex/texcoord/texkill, texbem(l), texreg2*, texm3x2/3x3 families, texdp3*, ps.1.4 phases,
  texld/texcrd/bem), each to HLSL through D3DCompile, cached.
- Caps exactly dgVoodoo 2.87's (read through it by `d3d8_frame caps`): vs.1.1, ps.1.4, RasterCaps 0x00736191 (table,
  vertex and range fog), 8 lights, 8 stages, 256 vertex shader constants.
- Present through a FLIP_DISCARD swap chain (DXGI stretches to the window), tearing when allowed and windowed; the gamma
  ramp drawn through when it isn't the identity. Reset rebuilds the back buffer and puts every state back to its default.
- Ashita: it wraps the device and draws through it; everything its ImGui DX8 backend and font/primitive objects use is
  above (state blocks, dynamic buffers, base vertex, viewports as clip rects, managed textures with partial locks).

**Real zones** (LOOK_GAME, the game's DATs drawn through Direct3D 8: fixed function and the game's own bump shaders,
textures, alpha test, fog; world target read back after the zone and after the characters):
Southern San d'Oria (1288 placements) 100.00% within 2, mean 0.001; West Ronfaure (8118) 99.99%, mean 0.005; Bibiki
Bay (4230) 99.99%, mean 0.000. What differs is isolated pixels (59 of 3.7 million in San d'Oria).

**HiFi XI on it (native probe, the real plugin):** identical to dgVoodoo in every case tried: the world named by the zone
marker (2560x1440, 39 markers seen, World FX in at the world's end); with the zone off and 12,000 UI quads, the world

layer reporting nothing but "no clear value" performance notes.

Found and matched along the way (dgVoodoo's behaviour, pixel for pixel): a stage reading a texture it hasn't got hands the
current colour/alpha on; empty stages in pixel shaders read white; A8 reads white; MIPFILTER POINT draws as LINEAR;
a stage not point sampled both ways is linear both ways (Phoenix's conf: Filtering 1, KeepFilterIfPointSampled);
projected coordinates divide by the fourth element; the reflection vector uses the local viewer even unlit and a unit
normal; the address register rounds to nearest; a viewport past the target is refused (the viewport kept).

## Differences from dgVoodoo that remain
- **Threading:** we record on the game's thread; dgVoodoo on its own. HiFi XI's hook callbacks (zone and character
  drawing at markers, World FX) now run on the game thread inside the game's D3D8 calls. Offline this works (the
  native probe, d3d8_hooks); what it costs the game thread in the field isn't measured.
- **List splits:** every 1024 draws (dgVoodoo: about 256 in the game). HiFi XI already handles markers at a list's head.
- **No merging** of consecutive DrawPrimitiveUP list draws (dgVoodoo merges them); same pictures, more draws.
- **Full screen** is presented in the window, never an exclusive mode or a display mode change.
- **Gamma** is applied always (windowed too) when not the identity; dgVoodoo's windowed behaviour wasn't compared.
- Not matched (not used by FFXI in any capture): BLENDTEXTUREALPHAPM (dgVoodoo comes out much brighter: formula not
  found); relative addressing at a0 = -1 / +1 in the vs.1.1 test (dgVoodoo reads something else there); a few line and
  point pixels; A8/L8/A8L8 as render targets and D16/D24 depth textures (dgVoodoo offers them; we say not available);
  indexed vertex blending (world matrices past 3 ignored); ProcessVertices; patches; point sprites / point size.
- dgVoodoo's adapter mode list (366 modes) is shorter than ours (all DXGI modes, X8R8G8B8 and R5G6B5).

## What HiFi XI would need to change
Nothing for it to run: its plugin code is unchanged here and passes on our stream. Worth doing once it's in:
- texts that name dgVoodoo (menu, logs: "dgVoodoo's OutputAPI must be d3d12_fl11_0") would be wrong;
- with recording on the game thread, HiFi XI's "a frame behind" ring and its mutexes are uncontended; nothing relies on
  the other thread (checked offline only).
